/ estándar SDD · plugin de Claude Code · v0.1.0

Spec-driven { ejecutable } para Claude Code.

tremen-sdd es un plugin de Claude Code: 7 skills de rol, 3 hooks y 5 scripts que implementan el flujo épica → spec → código verificado, con dos gates humanos (aprobación de spec y merge) y estados auditados en el frontmatter de cada artefacto.

los roles → los flujos
/ 01 — la idea

La estructura se scriptea,
el juicio se escribe.

Lo mecánico lo hacen scripts sin dependencias: scaffold.mjs numera y crea artefactos desde plantilla, estado.mjs valida cada transición contra la máquina de estados y firma el historial, tablero.mjs regenera el board desde los frontmatters. El LLM nunca asigna IDs ni edita estados a mano — solo redacta contenido.

SPEC-001-alta-factura.md frontmatter canónico 
id: SPEC-001
epica: EPIC-001
estado: en-revision
historial:
  - {estado: borrador,  por: sdd-arquitecto}
  - {estado: aprobada,  por: Alberto}   ← gate humano
  - {estado: en-progreso, por: sdd-implementador}
  - {estado: en-revision, por: sdd-implementador}
## Criterios de aceptación
✓ CA-1 · factura.ts:42 · factura.test.ts
— CA-2 · en verificación…
· en-revision el verificador decide GREEN o RED · el merge siempre es tuyo
/ 02 — las tres patas
01 / proceso

Pipeline de roles como subagentes.

Producto → arquitecto → implementador → verificador, cada uno con contexto aislado y comunicándose solo por artefactos. Gates humanos en aprobación de spec/ADR y en el merge. Si el verificador da RED, los findings vuelven al implementador — máximo 3 iteraciones, luego escala al humano.

ver los flujos
02 / enforcement

Tres hooks PreToolUse / PostToolUse.

require-spec deniega Edit/Write en rutas vigiladas sin rama ft/SPEC-NNN y spec en aprobada/en-progreso. protege-verdad restringe FOUNDATION.md y docs/fundacion/ a sus dueños. calidad devuelve linter y coherencia de frontmatter con exit 2. Todos fail-open: sin .sdd.json, no intervienen.

qué comprueba cada uno
03 / evidencia

Ledger: CA → código → test → verificación.

Cada spec lleva un ledger con la matriz criterio → fichero → test → veredicto, con escritores separados (el implementador rellena su mitad; el verificador la suya). La evidencia visual va a _qa/SPEC-NNN/ y informe-qa.mjs ensambla un acta HTML autocontenida (capturas y vídeo en base64).

/ 03 — instalar

Instalación y arranque. 

# una vez, en tu máquina
claude plugin marketplace add tremen-dev/tremen-sdd
claude plugin install tremen-sdd@tremen-sdd

# en cada proyecto (nuevo o migración)
/sdd-init
